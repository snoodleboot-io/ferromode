PythonCopy import numpy as np import ferromode_py as fm # Composite signal: two sinusoids t = np.linspace(0, 4.0, 1024) signal = np.sin(2 * np.pi * 8 * t) + np.sin(2 * np.pi * 2 * t) # Decompose config = fm.EmdConfig(max_imfs=4, sd_threshold=0.2) result = fm.emd(signal, config) imfs = result.imfs().imfs() # ndarray (n_imfs, N) residue = result.imfs().residue() # ndarray (N,) print(f"Extracted {result.imfs().n_imfs()} IMFs in {result.elapsed_ms():.1f} ms") print(f"Reconstruction error: {result.imfs().orthogonality_index():.2e}")

Core Concepts

Intrinsic Mode Functions (IMFs)

An IMF must satisfy two conditions: (1) the number of extrema and zero-crossings differ by at most one; (2) the mean of the upper and lower envelopes is zero everywhere. EMD extracts IMFs from highest to lowest instantaneous frequency, so IMF 1 captures the fastest oscillations and each subsequent IMF represents slower variation. The final residual is the trend.

The Sifting Process

  1. Detect all local maxima and minima in the current signal
  2. Fit cubic splines through the maxima (upper envelope) and minima (lower envelope)
  3. Compute the envelope mean: m = (upper + lower) / 2
  4. Subtract: h = signal − m
  5. Check stopping criterion; if not met, repeat from step 1 on h

Once an IMF is accepted, it is subtracted from the signal and the outer loop repeats on the residual until fewer than two extrema remain.

Stopping Criteria

Ferromode supports four stopping criteria — only one needs to be chosen per run:

Math # SD threshold (default, matches PyEMD) SD = Σ |h[k] − h[k-1]|² / Σ |h[k-1]|² < threshold (default: 0.2) # S-number: stop after S consecutive passes where # |#extrema − #zero-crossings| ≤ 1 # Fixed iterations: stop after exactly N sifts # Energy difference: stop when ΔE < threshold

Boundary Conditions

How the signal is extended past its edges determines envelope quality at the boundaries and therefore affects every IMF. Ferromode ships six strategies:

Name Flag Best for
ExtremasMirror (default) extrema General-purpose; broadband aperiodic signals
MirrorEven mirror Symmetric bursts; sparse boundary extrema
Periodic (Zhao & Huang 2001) periodic Cyclic records: sunspots, tides, rotating machinery
Slope slope Signals with a strong linear trend at the edges
AR Model ar Stationary processes where an AR fit is reliable
WaveformMatching waveform Recurring motifs: ECG beats, mechanical transients

Signal length Median (ms) Typical range
500 samples ~10 ms 8–12 ms
1,000 samples ~10 ms 9–14 ms

10,000 samples ~31 ms 28–38 ms

Time Complexity

Each sifting step performs one O(n) extrema detection pass and one O(n) tridiagonal spline solve. Let K = number of IMFs extracted and M = average sifting iterations per IMF. Total work is:

Math T(n) = O(n · K · M) K ≈ log₂(n / f_min) in practice (signal-dependent) M ≈ 5–20 for SD threshold 0.2 n = signal length Ensemble methods multiply by num_ensembles but are embarrassingly parallel.

This is not O(n log n) — that would require the cubic spline solve to use FFT-based methods, which it does not. The tridiagonal solver is O(n) per call, so EMD is O(n) per sifting step, and O(n·K·M) overall.

Benchmark Script

PythonCopy # scripts/bench_emd.py — reproduce the table above import subprocess, tempfile, os, time import numpy as np BINARY = "target/release/ferromode_run" RUNS = 5 for n in [500, 1000, 5000, 10000]: rng = np.random.default_rng(42) t = np.linspace(0, 4.0, n) sig = (np.sin(2*np.pi*32*t) + np.sin(2*np.pi*8*t) + np.sin(2*np.pi*2*t) + 0.1*rng.standard_normal(n)) with tempfile.NamedTemporaryFile(suffix=".csv", mode="w", delete=False) as f: inp = f.name for v in sig: f.write(f"{v}\n") out = inp.replace(".csv", "_out.csv") times = [] for _ in range(RUNS): t0 = time.perf_counter() subprocess.run([BINARY, "--input", inp, "--output", out, "--max-imfs", "6", "--sd-only", "--sd-thr", "0.2"], capture_output=True) times.append((time.perf_counter() - t0) * 1000) os.unlink(inp) if os.path.exists(out): os.unlink(out) times.sort() print(f"n={n:>6}: median={times[RUNS//2]:.1f} ms")

Frequently Asked Questions

What is the difference between EMD, EEMD, CEEMDAN, and ICEEMDAN?

▼

EMD (Huang et al. 1998) is the baseline algorithm. It is fast and deterministic but prone to mode mixing when the signal has intermittent components or abrupt changes.

EEMD (Wu & Huang 2009) runs EMD on many copies of the signal with different white-noise realisations, then averages the IMFs. The noise cancels on average, producing cleaner mode separation. Cost: num_ensembles × EMD.

CEEMDAN (Torres et al. 2011) adds adaptive white noise at each sifting stage rather than once at the start, giving better reconstruction and fewer spurious IMFs than EEMD.

ICEEMDAN (Colominas et al. 2014) further improves CEEMDAN by using the local mean operator directly, reducing residual noise in the extracted IMFs. It is the recommended choice for financial and geophysical time series.

How do I choose the SD threshold?

▼

The default of 0.2 matches PyEMD and the original Huang et al. recommendation — it works well for most signals. Lower values (0.05–0.1) produce more strictly symmetric IMFs but increase computation time. Higher values (0.3–0.5) converge faster but may leave residual asymmetry in the envelopes. If you care only about the dominant frequency of each IMF and not fine amplitude accuracy, 0.2–0.3 is fine.

Why is the number of IMFs different each run?

▼

EMD is data-adaptive — the number of IMFs depends on the signal structure, not a fixed parameter. The outer loop terminates when the residual has fewer than two maxima and two minima, so shorter signals or signals with fewer oscillatory scales produce fewer IMFs. Ensemble methods additionally vary because each noise realisation shifts the extrema positions slightly. Use max_imfs to cap the count if you need a predictable output shape.

What does "mode mixing" mean and how do I reduce it?

▼

Mode mixing occurs when a single IMF contains oscillations at very different frequencies, or when components of similar frequency are split across multiple IMFs. It is most common when the signal has intermittent components or a wide instantaneous frequency range.

Use CEEMDAN or ICEEMDAN to reduce mode mixing — the controlled noise injection activates all frequency scales uniformly so each IMF captures a narrower band. ICEEMDAN is the strongest option.

Which boundary condition should I use?

▼

Start with the default ExtremasMirror. It works well on most signals without any configuration. Switch to Periodic if your signal is genuinely cyclic over the observation window (e.g. sunspot numbers, tidal records). Use WaveformMatching if your signal has recurring waveform templates (e.g. ECG beats, mechanical vibration). The boundary showcase on the Examples page shows side-by-side comparisons on a known synthetic.

Can ferromode process signals in real time?

▼

EMD is a batch algorithm — it needs the whole window to find the global extrema. For streaming use, buffer incoming samples into overlapping windows and process each window independently. The 10 ms latency at 1,000 samples is fast enough for most sensor-fusion pipelines at update rates up to ~100 Hz. The Python bindings expose a StreamingDecomposer class that manages the buffer and overlap automatically.

How do I verify that the decomposition is correct?

▼

Check two things: (1) perfect reconstruction — result.imfs().reconstruct() should match the original signal to floating-point precision; (2) orthogonality index — result.imfs().orthogonality_index() measures the cross-correlation between IMFs; values below 0.01 indicate good separation. Ferromode validates reconstruction automatically and raises an error if it exceeds the configured tolerance (default: 1 × 10⁻¹²).
